## 维度 1：大模型工作原理与五项基础能力

**核心判断：前四项是 LLM 原生能力，第五项是连接范式。**

| 能力 | 定义 | 关键动作 |
|---|---|---|
| 提示词工程 | 需求翻译成稳定可执行的指令 | 角色/任务分解/CoT/few-shot/JSON Schema 输出约束 |
| 上下文工程 | 决定「何时、给什么」信息 | 窗口管理、信息压缩、选择性注入、防指令稀释 |
| Harness 工程 | Agent 运行骨架 | 编排、循环调度、工具调度、状态管理、重试、可观测 |
| Function Call | 模型调用工具的协议 | 参数结构化、多轮/并行调用、失败回退兜底 |
| Skill/MCP/Plugin | 模型—工具连接范式 | MCP 客户端/服务端、能力发现、能力治理 |

**三者边界（核心）：**

```
Function Call = 协议层（模型如何调用工具）
MCP          = 连接标准（工具/数据源统一接入协议，跨模型跨厂商）
Skill        = 能力单元（领域知识的可复用 prompt+工具包）
Plugin       = 扩展机制（插件化注册第三方/自建能力）
```

| 对比维度 | Function Call | MCP | Plugin/Skill |
|---|---|---|---|
| 本质 | 模型输出格式约定 | 服务端-客户端协议 | 能力封装单元 |
| 解决问题 | 模型如何调用工具 | 如何统一接入工具/数据 | 如何复用/治理能力 |
| 关系 | 底层协议 | 传输+发现层 | 上层组织层 |

## 维度 2：Agent 范式理解与选型

**核心判断：选型是「按需求特征匹配架构」，不是「越复杂越好」。**

| 范式 | 适用场景 | 优点 | 代价 |
|---|---|---|---|
| Workflow（固定编排） | 确定性、流程固定 | 可控、稳定、成本低 | 低 |
| ReAct | 单步推理+工具调用 | 简单、可解释 | 中 |
| Plan-and-Execute | 复杂多步任务 | 先规划后执行 | 中高 |
| Reflection | 需自我纠错/优化 | 质量高、可迭代 | 高 |
| Multi-Agent | 多角色分工 | 专业化、可扩展 | 高 |

**选型方法：需求特征四问 → 匹配范式**

```
确定性/探索性？ 单步/多步？ 是否协作？ 成本延迟敏感？
```

| 需求特征 | 确定性 | 探索性 |
|---|---|---|
| 单步/固定流程 | Workflow | — |
| 多步+工具 | ReAct | Plan-and-Execute |
| 自我纠错 | — | Reflection |
| 多角色分工 | — | Multi-Agent |

**选型理由模板：** 场景 → 需求特征 → 选 X 范式 → 权衡（可控性/成本/延迟）→ 预期效果。

## 维度 3：主流 Agent 框架掌握

**核心判断：懂边界 + 会踩坑规避，而非仅会调 API。**

| 框架 | 定位 | 核心机制 |
|---|---|---|
| LangGraph | 图式状态机编排 | Checkpointer、状态管理、HITL、可观测 |
| LangChain | 链式编排 | Chain、LCEL |
| DeepAgent | 长任务多步自主 | 子任务分解、自我纠错 |
| OpenAI SDK | 原生轻量可控 | Function Calling、Tool Use、结构化输出、流式 |

**选型取舍：**

```
开发效率：LangChain > LangGraph > OpenAI SDK
可控性：OpenAI SDK > LangGraph > LangChain
可观测性：LangGraph > 其他
成本控制：OpenAI SDK > LangGraph > LangChain
```

**五大坑与规避：**

| 坑 | 规避 |
|---|---|
| 上下文泄漏 | 会话隔离 + 滚动摘要 + 精确注入 |
| 循环失控 | 最大步数限制 + 循环检测 + 终止条件 |
| 工具调用失败无兜底 | try-except + fallback + 降级 |
| 状态不一致 | Checkpointer 持久化 + 幂等设计 |
| Token 成本失控 | 缓存 + 检索压缩 + 模型分级 |

**低代码/多智能体平台（加分）：** Dify、Coze、AutoGen、通义——快速验证用低代码，生产可控用框架。

## 维度 4：业务场景落地经验（重点）

**核心判断：权重最高的考核维度，看真实项目而非理论。**

**落地四环节：**

```
落地背景 → Agent 选型 → 实施过程（里程碑/坑/决策）→ 业务结果（可验证/可复用/可度量）
```

**项目弹药映射：**

| 项目 | 覆盖维度 |
|---|---|
| FastAPI + LangGraph 生产化 Agent | Harness、Function Call、LangGraph |
| mem0 + pgvector 双层记忆架构 | 上下文工程、Harness |
| Celery + llama_index + Elasticsearch 混合检索 | 上下文工程、工程基础 |
| APScheduler 分布式锁缺陷修复 | Harness、工程基础 |
| DataAgent 多智能体架构规划 | Agent 选型、Multi-Agent |
